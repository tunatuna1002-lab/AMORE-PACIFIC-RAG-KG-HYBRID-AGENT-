# Ablation 스터디 — 2026-08-30 (플래그 실배선 후 재실행)

## 배경

기존 ablation(2026-08-24 보고서)의 `no-kg`/`no-ontology` arm은 해당 피처 플래그를
읽는 코드가 없어 **사실상 no-op**(full과 동일 구성)이었다. 2026-08-30 플래그를
실제 분기에 배선한 뒤(커밋 d930085) 전 구성을 재실행했다. 이번 실행에서는
no-kg의 지연이 12.6→8.8초로 감소해 실제로 컴포넌트가 꺼졌음이 확인된다.

## 조건

subset_nokg.jsonl 30문항(재매핑판) / gpt-4.1-mini / temp 0.1 / top-k 8 /
LLM Judge(gpt-4.1-mini) + semantic similarity / 외부신호 OFF / concurrency 4 /
프롬프트 v1b(근거 인용 강화) / 구성당 1회.

### 컴포넌트 기여도 (full 대비 overall Δ)

- KG: **+0.015** (제거 시 하락 — 단, 본 subset은 requires_kg=false 문항이라 과소평가됨)
- Ontology 추론: +0.006 (미미)
- Confidence Fusion: +0.003 (미미)
- Query Rewriter: -0.005 (미미하게 부정적)
- **Reranker(관련성 채점): -0.020 (부정적) + 지연 +7.4초**

## 핵심 발견 — Reranker가 근거성을 해친다

`no-reranker`에서 groundedness가 0.237→**0.414 (+75% 상대)**로 최대 개선이며,
relevance도 최고(0.855), L2 recall 손실 없음, 지연 59% 감소.

**메커니즘 해석**: LLM 기반 relevance grader가 검색 문서를 보수적으로 걸러내
컨텍스트가 얇아지고, 모델이 컨텍스트 밖 지식으로 답변하게 되어 근거성이
하락한다. grading 자체의 LLM 왕복 비용(+7.4초)까지 고려하면 현 코퍼스
규모(271청크)에서는 순손실이다.

## 조치

- `config/feature_flags.json`의 `retriever.use_reranker`를 **false**로 전환
  (환경변수 `FF_RETRIEVER_USE_RERANKER=true`로 언제든 재활성 가능)
- 160문항 전체셋 재측정으로 검증 → baseline v2.0 (별도 기록)
