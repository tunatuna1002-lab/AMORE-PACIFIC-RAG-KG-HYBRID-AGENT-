# 개선 사이클 3 — 측정 인프라 결함 발견과 정합화 (2026-08-30)

## 핵심 발견: 동시 실행 트레이스 오염 (측정 자체가 틀려 있었다)

v3.0 리포트 진단 중 **HHI 질문(lg042)의 트레이스에 sos 개념**이 찍혀 있는 것을
단서로, concurrency>1 평가 시 공유 에이전트의 `_last_hybrid_context`가 경쟁
상태로 덮어써져 **문항 트레이스가 다른 문항의 컨텍스트를 캡처**하던 결함을
확인했다. L1/L2/L3 전 지표와 groundedness(트레이스 기반 컨텍스트로 채점)가
무작위 오염되어, **기존 baseline(v1.0~v3.0)의 트레이스 지표는 전부 하향 왜곡**
상태였다.

수정: `chat()` 결과에 요청별 hybrid_context 동봉, 러너가 이를 우선 사용
(커밋 5b64536, 회귀 테스트 포함).

## 추가 정합화 (v4.0 → v4.1)

1. **L1 generic 오탐 제거** (920b54a): 골드 어휘에 없는 brand·product·comparison·
   trend·ranking·price 방출 제거 (오탐 상위 brand 48건·ranking 35건·product 31건)
   + indicator ranking→product_ranking 별칭.
2. **제품명 슬러그 엣지** (fe59df7): L3 최다 미스가 `laneige -hasProduct->
   lip_sleeping_mask`형(28문항) — KG는 ASIN 객체라 매칭 불가. 상위 랭크(≤10)
   제품 브랜드당 2개를 제품명 슬러그(3·2단어 변형)로 방출.
3. **concept 게이트 재보정** (fe59df7): 클린 분포(중앙값 0.40) 기준 0.5→0.3 —
   기존 임계는 상위 문항까지 fail 처리해 판별력이 없었음. L1_concept_fail
   100→64건으로 게이트가 하위 구간을 분별하게 됨.

## 전 사이클 누적 (v1.0 → v4.1, 하루 동안)

overall 0.428→0.507 (+18%), groundedness 0.365→0.650 (+78%),
지연 12.7s→8.3s (-35%). 단 v1.0~v3.0은 트레이스 오염으로 하향 왜곡돼
있었으므로 레이어 지표의 절대 비교는 v4.0 이후만 유효.

## 남은 과제

1. L3 Edge F1 0.211 — 제품명 슬러그로 일부 회복했으나 여전히 최다 fail 태그
   (125문항). 골드 엣지 유형별 잔여 미스 재진단 필요 (rank>10 제품, 브랜드
   미추출 문항, set-F1 설계).
2. L1 entity 0.487 / mapping fail 72문항 — 브랜드 표기 변형(tirtir 등) 커버리지.
3. RAG 코퍼스 확충 — L2 recall 0.222는 클린 측정에서도 낮음 (코퍼스 271청크).
