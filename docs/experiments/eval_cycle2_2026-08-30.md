# 개선 사이클 2 — L2·L1·L3 병목 해소 (2026-08-30)

## 배경

baseline v2.0의 진단: groundedness 0.39(코퍼스·컨텍스트 부족), L1 concept 0.12
(어휘 체계 불일치), L3 edge 0.21(KG에 메트릭 엣지 부재). 세 병목을 로컬 진단으로
원인 확정 후 수정했다.

## 진단 → 수정

| 병목 | 진단 (v2.0 리포트 로컬 분석) | 수정 |
|---|---|---|
| L2/근거성 | top-k 8로 검색해놓고 컨텍스트 상한이 **3청크** (153/160 문항이 정확히 3개) | `max_context_items.rag_chunks` 3→8 |
| L1 concept | 골드는 분석 개념(sos·time_series·competitor_analysis...), 추출은 카테고리(beauty·lip_care)만 방출. `extract_concepts()`는 **구현만 있고 호출처 0건** | EntityExtractor→entities['concepts'] 배선 + 트레이스/지표 연결 + 택소노미 analysis_concepts 29종 |
| L3 edge | KG에 hasSoS/competesWith 엣지 자체가 없음 — `KGEnricher` 역시 **호출처 0건** | daily crawl에 엔리치먼트 배선 + 백필 실행 (KG 1,028→2,700 트리플) + 트레이스 엣지 표면화 |

중간 검증(1차 160문항)에서 엣지 20개 무차별 노출이 L3 edge F1을 오히려
악화시키는 것을 확인(정밀도 붕괴) → 쿼리 관련 엣지 8개 상한으로 조정 후 재실행.

## 남은 문제 (다음 사이클)

1. **L3 Edge F1 회귀**: 엣지 표면화 자체는 성공(85/160 문항에 hasSoS/competesWith)
   했으나, ① 골드가 기대하는 *특정* 경쟁사(cosrx·burts_bees)와 노출 competesWith
   상위 3개(삽입 순서 기준)가 불일치, ② 열린 검색 집합에 set-F1을 적용하는 지표
   설계 자체가 탐색 폭을 벌점화. → competitor를 SoS 기준 상위로 정렬해 노출하거나,
   지표를 recall 중심으로 재설계 검토.
2. **L1 Concept 0.145**: 개념은 흐르지만(문항당 2개 수준) 골드는 3~4개 —
   multi_hop 등 구조 태그는 키워드 매칭 불가. 골드 어휘 정리 또는 LLM 기반
   개념 태깅 검토.
3. 게이트 통과율은 여전히 0~2건 수준 — L1 concept(임계 0.5)·L3 edge(0.5) 게이트가
   현 지표 수준과 괴리. 지표가 안정되면 임계 재보정 필요.
