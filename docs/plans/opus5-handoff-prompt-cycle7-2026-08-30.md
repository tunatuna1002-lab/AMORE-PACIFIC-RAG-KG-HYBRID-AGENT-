## 작업 (우선순위순)
1. **교차언어 검색 갭** — 지금 가장 실체 있는 제품 결함. 한국어 질의가 영문 IR 청크
   (코퍼스의 88%)에 도달하지 못한다. 먼저 무비용으로 갭의 크기를 수치화하라(한국어/영어
   질의쌍으로 IR 청크 회수율 비교). 해법 후보는 두 갈래다: (a) 질의 확장/번역 — 저비용,
   기존 query_enhancer 경로에 얹을 수 있음, (b) 다국어 임베딩 모델 교체 — 전체 재색인
   필요(2,242청크 재임베딩), 임베딩 캐시·기존 컬렉션 마이그레이션·검증까지 포함하는
   파괴적 변경. (a)를 먼저 소규모로 실측하고, (a)로 부족함이 수치로 확인될 때만 (b)를
   검토하라. 어느 쪽이든 결정 근거를 experiments 문서로 남긴다.
2. **골든셋 L2 라벨 재설계** — 개념당 청크 집합 골드. scripts/remap_golden_chunk_ids.py의
   관례(매핑 근거 주석, dry-run, 재현 가능)를 따르고, 지표(l2_retrieval)·게이트(aggregator)·
   eval/README 게이팅 표·테스트를 함께 정합시켜라. 골드가 바뀌면 이전 baseline과 L2 비교가
   단절된다 — 새 baseline 문서에 이를 명시하라. 골든셋에 IR 도메인 문항이 0개인 문제
   (사이클 5 5절 3항)는 이 재설계와 함께 설계만 검토하고, 문항 추가는 10~15문항 이내로
   보수적으로 판단하라 — 골든셋 확장은 기존 문항의 검증 관례(실데이터 기반 gold)를 따를 것.
3. **소셜 수집기 4종 삭제** — 위 결정대로. 독립 커밋으로 분리하라.

각 작업은 계획서 3절의 사이클 루프(무비용 진단 → 수정 → 테스트 → 필요시 subset 스모크 →
160문항 본실행 → compare → set-baseline → 문서화 → 커밋 → push)를 따른다.

## 판단 원칙
- 사용자가 요청한 것을, 의도한 범위에서 완수하라. 애매함은 신중한 동료가 하듯 해석하고,
  해석에 따라 결과물이 실질적으로 달라질 때만 확인을 구하라. 더 나은 접근이 보이면 한
  문장으로 말하고 요청된 작업을 계속하라 — 조용히 범위를 좁히거나 넓히거나 변형하지 마라.
  작업 전체를 끝내라. 정말 끝낼 수 없는 부분이 있으면 나머지를 끝내고 무엇이 왜 남았는지
  명시하라.
- 돈이 드는 실행 전에 반드시 v6.0 리포트와 무비용 시뮬레이션으로 원인·효과를 수치로
  확정하라. 사이클당 160문항 본실행은 1~2회가 상한이다. 임베딩 재색인도 비용이다 —
  재색인은 설계가 확정된 뒤 1회만.
- 지표·골든셋·게이트를 결과가 좋아 보이도록 조정하지 마라. 라벨 재설계의 기준은 "점수가
  오르는가"가 아니라 "골드가 원래 의도(문서 수준 의미)를 정확히 표현하는가"다. 재설계
  전후 점수 변화는 개선이 아니라 측정 변경이므로 그렇게 보고하라. 나빠진 지표도 그대로
  보고하라 — 이 리포의 가치는 정직한 측정 기록이다.
- 평가 실행 조건은 계획서 1절의 표준 명령을 그대로 써라. FF_AGENTS_USE_EXTERNAL_SIGNALS=false는
  Tavily 월 쿼터 보호용이니 바꾸지 마라. .env 값은 읽되 어디에도 출력·기록하지 마라.
